核心概念

变异测试状态

状态含义
killed测试失败 —— 测试发现了变异（好）
survived测试通过 —— 漏测（报告会给出代码位置与上下文）
timeout执行超时（单独统计）
equivalent等价变异（人工标记 / 启发式，不计入得分）
error构建 / 执行错误（不计入得分但需报告）

变异得分

Mutation Score = killed / (killed + survived + timeout)

等价变异体（equivalent）从分母排除。

元测试自检（差异点）

metatest selftest 运行内置 17 个已知答案基准项目，验证平台不会把失败误报为通过、把跳过误判为成功。自检失败 → 退出码 3 → CI 必须失败。

类型已知答案
py_must_fail / c_must_fail测试必失败 → 平台必须判 fail
py_must_pass / c_must_pass / command_must_pass测试必通过 → 平台必须判 pass
py_skip / py_all_skipped跳过 ≠ 通过 → 必须判 pass_with_skips / all_skipped
py_timeout必超时 → 平台必须判 timeout 并终止进程
py_weak_assert弱断言必须被质量分析标记
py_flaky交替失败必须被 flaky 检测识别
py_mutant_kill / c_mutant_kill / py_mutant_survive指定变异必须被杀死 / 存活
py_equivalent_manual人工标记的等价变异 → equivalent（不计入得分分母）
py_equivalent_suspectdunder 内返回值变异 → 必须带「疑似等价」启发式标记
c_lexical_guard宏 / 字符串 / 注释区域零变异体、零 error（词法误伤防护）

适配器协议（多语言接入）

统一接口：detect() / prepare() / generate_mutants() / run_tests() / parse_result() / cleanup()

  • python：AST 变异 + pytest / unittest（JUnit XML 统一结果输入）
  • c：tree-sitter 变异引擎（无依赖时词法级回退），支持 gcc / Make / CMake+CTest
  • command：任意项目命令级接入——提供 build / test 命令与结果格式即可获得 flaky 检测、结果校验与报告；配置 mutation.rule_files 后还能做规则化变异
  • 第三方：通过插件模板新增变异算子或适配器，运行 metatest plugins template 导出模板

命令参考

命令说明
metatest init [dir]生成 metatest.yaml（探测语言 + 推断布局 + 登记信任）
metatest run [--incremental --diff-ref main]全量 / 增量变异评估
metatest run --test-selection测试关联筛选：只跑覆盖变异行的测试（仅 Python/pytest）
metatest selftest [--list]元测试自检
metatest flaky --runs 3 --isolateflaky 检测 + 隔离分类（孤立 flaky vs 顺序依赖）
metatest quality [--strict]弱断言 / 重复测试 / flaky 分析
metatest report --results results.json --format html --out report.html生成 HTML / JSON / JUnit 报告
metatest ci github / gitlab输出官方 CI 模板
metatest ui [--project DIR --port N]启动本地 Web 控制台
metatest plugins template导出插件模板
metatest allow / deny登记或撤销对某配置的信任（用户级存储）

CLI 退出码

退出码含义
0成功且达到质量门禁阈值
1质量门禁失败（变异得分低于阈值 / flaky / 弱断言超限）
2平台 / 配置错误（配置无效、环境缺失、基线测试失败、不可信配置）
3元测试自检失败（平台自身不可信，CI 必须失败）

CI 集成

metatest ci github     # 输出官方 GitHub Actions 模板
metatest ci gitlab     # 输出官方 GitLab CI 模板

界面里看到的通过与否，CI 里也是同样结论——每个动作最终落到 CLI 参数，结果来自同一份 .metatest/report/results.json，退出码语义一致。

CI 中命令执行需一次性放行：可用 --allow-commands 或环境变量 METATEST_ALLOW_COMMANDS=1。

项目结构

metatest/ ├── cli/ # CLI 入口（init/run/selftest/flaky/quality/report/plugins/ci/ui） ├── core/ # 调度引擎、沙箱、缓存、增量筛选、质量分析 ├── adapters/ # python / c / command 适配器 + 插件注册 ├── mutators/ # python AST 变异器、c tree-sitter 变异器 ├── metatests/ # 已知答案基准项目库（17 个） ├── plugins/ # 插件加载与模板 ├── report/ # HTML / JSON / JUnit XML 报告 └── web/ # 本地 Web 控制台：HTTP API + SSE 日志 + 前端静态资源
软件化交付：metatest ui 启动本地控制台，python scripts/build_exe.py 产出单文件 dist/MetaTest.exe（约 25 MB，双击即用）。

安全模型

控制台会执行 metatest.yaml 里的命令，保留 CLI 信任模型，并额外加三道本地防护：

  1. 仅回环监听 + Host 校验：默认 127.0.0.1，拒绝非 localhost 的 Host 头，防 DNS rebinding。
  2. 写操作自定义头 X-Metatest-Client: web：跨站表单无法伪造。
  3. 命令执行需显式确认：信任存用户级 ~/.metatest/trusted.json，仓库内容无法自我授权；报告读取限制在项目 .metatest/report 目录内，防路径穿越。
不要把 --host 改成 0.0.0.0：该服务没有鉴权，只面向本机单用户（MVP 不做 SaaS）。团队共享走 CI 集成。

FAQ

支持哪些语言？
内置 Python、C、Command 适配器；通过插件模板可扩展。详见适配器协议。
是否会上传我的代码？
不会。本地优先，所有执行在你的机器 / 内网完成，不向外部服务发送代码。
如何接入 GitHub Actions / GitLab CI？
metatest ci github / metatest ci gitlab 输出官方模板，按退出码设置门禁。
自检失败怎么办？
退出码 3，CI 必须失败。检查环境（解释器 / 依赖），或提交 issue 附自检日志。
等价变异体怎么处理？
等价变异不计入得分分母，可人工标记或启发式提示。
「基线测试 0 个用例」是什么原因？
几乎都是解释器问题：PATH 上的 python 不是装了 pytest 的那个。用 metatest python --set <路径> 绑定，或在 metatest.yaml 写绝对路径。
