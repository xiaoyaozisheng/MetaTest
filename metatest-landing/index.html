问题

测试通过，不等于测试有效

普通测试工具回答「产品有没有 bug」。MetaTest 回答三个更上层的问题：

现有测试是否有效？

生成源码微小变异，看测试能否「杀死」它们——杀死越多，测试越能发现真实缺陷。

测试质量是否在退化？

持续检出弱断言、flaky、重复测试与「高覆盖率低得分」，防止绿了却没测到。

测试工具本身是否可信？

用 17 个已知答案的基准项目自检平台判断；自检失败，CI 必须失败。

信任核心

我们如何证明 MetaTest 自己可信？

不靠「专业、准确」的空话——靠 17 个已知答案的基准项目逐项验证。

17
已知答案基准项目
3
自检失败 → 退出码 3 → CI 必须失败
0
误判容忍：失败不能报通过，跳过不能算成功
  • *_must_fail / *_must_pass：必失败 / 必通过判定正确
  • py_skip / py_all_skipped：跳过 ≠ 通过
  • py_timeout：必超时并终止进程
  • py_weak_assert / py_flaky：质量分析必须检出
  • *_mutant_kill / *_mutant_survive：指定变异死活准确
  • py_equivalent_*：等价变异不计入得分分母
  • c_lexical_guard：宏 / 字符串 / 注释区域零误伤

边界

CI/CD、部署方式与安全

使用方式（MVP 不做 SaaS）

  • 本地运行：metatest ui 启动本地控制台，或直接用 CLI
  • CI 集成：退出码驱动门禁，GitHub / GitLab 官方模板
  • 私有化部署：全部在你的机器 / 内网执行，数据不出内网
当前不提供在线 SaaS 服务；控制台为本地工具，不托管用户代码。

安全模型（默认只本机）

  • 仅回环监听 127.0.0.1，拒绝非 localhost 的 Host 头，防 DNS rebinding
  • 写操作要求自定义头 X-Metatest-Client: web，跨站无法伪造
  • 命令执行需显式确认，信任存用户级，仓库内容无法自我授权

CI 退出码语义

退出码含义CI 行为
0成功且达到质量门禁阈值通过
1质量门禁失败（变异得分低 / flaky / 弱断言超限）失败
2平台 / 配置错误失败
3元测试自检失败（平台自身不可信）必须失败
FAQ

常见问题

支持哪些语言？
内置 Python（AST + pytest/unittest）、C（tree-sitter，无依赖时词法级回退）、Command（任意命令级接入）。通过插件模板可扩展更多语言与变异算子。
是否会上传我的代码？
不会。MetaTest 是本地优先工具，所有变异生成与测试执行都在你的机器 / 内网完成，不向任何外部服务发送代码。MVP 不做 SaaS。
如何接入 GitHub Actions / GitLab CI？
运行 metatest ci github 或 metatest ci gitlab 输出官方模板，按退出码（0 通过 / 1 门禁失败 / 3 自检失败）设置门禁即可。详见文档 · CI 集成。
自检失败怎么办？
自检失败（退出码 3）说明平台自身判断不可信，此时一切结论都不可信，CI 必须失败。请检查环境（解释器 / 依赖），或提交 issue 附上自检日志。
等价变异体怎么处理？
等价变异（语义与原代码相同，不可能被杀死）不计入得分分母。可人工标记或启发式提示，避免拉低真实得分。
控制台能部署到公网给团队用吗？
不建议。控制台设计为仅本机单用户、无鉴权，文档明确不要把 --host 改成 0.0.0.0。团队共享建议走 CI 集成，而非公网暴露控制台。
